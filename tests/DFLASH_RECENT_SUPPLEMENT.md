# Recent256 / Recent64 / Recent0 supplement

`bash tests/train_dflash_recent_supplement.sh` adds exactly three new models to
the completed experiment-1 group:

```
runs/dflash_exp1_10w_5ep_mb4_acc8_20261110_154705_2794634
```

`BASELINE_RUN_GROUP` can select another compatible original group explicitly.
There is no implicit latest-run lookup for this launcher. Five old models
(Full, Recent128, Pivot1, Pivot5, Pivot12) are read-only controls.

## Exact context semantics

| Mode | Visible Target positions before anchor a | Current Draft block |
|---|---|---|
| recent256 | `[max(0,a-256),a)` | anchor + 7 MASK tokens |
| recent64 | `[max(0,a-64),a)` | anchor + 7 MASK tokens |
| recent0 | none | anchor + 7 MASK tokens only |

Windows count sequence positions, including visual positions if they occur
inside the window, exactly as the existing Recent128 implementation does.
The Target always keeps its full original multimodal input and verification
cache. The anchor is a fixed token ID embedded using the frozen Target token
embedding; Recent0 receives no Target hidden, pivot hidden, recurrent state,
visual adapter or learned null context slot. Frozen Target hidden may still be
computed for training teacher diagnostics, but is never a Recent0 Draft input.

Recent0 has physically zero context keys during training and inference.
Independent training blocks see only their own eight tokens. Original absolute
RoPE positions and the usual noncausal attention within each block are kept.
The context projector/norm have no trainable parameters in Recent0. It cannot
retain a cross-round Draft KV cache, and its inference path requests no Target
hidden output. The explicit empty branch avoids the Python `[-0:]` pitfall.
Bounded inference tensors are cloned after truncation so a short view cannot
retain the storage for the entire prefix. This does not change old weights or
visibility; old controls are evaluated again with the same updated runtime.

## Training

The preparation helper reads all five old `effective_config.json` files and
`experiment.json`, checks matched hyperparameters, hashes the original JSONL,
checks the compatible preflight/eligible-set fingerprints, and verifies all
five old epoch-5 exports against their frozen evaluation manifest. Missing or
changed source data/configs/exports fail before training. It also verifies the
hashes and 32-sample selection of all eight old evaluation datasets.

Each generated YAML copies the effective Full recipe, changing its context,
output directory and export settings. Original learning rate, decay, warmup,
seed, anchors, optimizer and all other training choices are inherited.
Three Drafts initialize independently from scratch with a fresh optimizer and
schedule; the frozen Qwen3.5 Target loads normally. No old Draft is used to
initialize them. No new raw dataset conversion is needed.

* Three models run sequentially, each on **4 or 8 GPUs**, selected by `TRAIN_GPUS`.
* **5 epochs**, micro batch **4**, global batch **256**: accumulation **16**
  with four GPUs, or **8** with eight GPUs. Learning rates are inherited;
  per-rank sample counts and optimizer steps are recomputed and recorded.
* Block size **8**, **5** Draft layers, **512** sampled anchors, image cap **1024**.
* The original 10w candidate JSONL/preflight is reused: normally **95,420**
  candidates and **56,712** eligible samples. The launcher checks the actual
  source counts and hashes rather than silently substituting another dataset.
* Every epoch is exported (`epoch_1` ... `epoch_5`, plus `last`). No optimizer
  training-state files are saved. Comparisons explicitly use `epoch_5`.

Default new output: `runs/dflash_recent_supplement_<N>gpu_10w_5ep_mb4_acc<A>_<time>_<pid>`.
`RECENT_RUN_GROUP` must identify a fresh directory. It may be a new child of
the old group, for example
`$BASELINE_RUN_GROUP/recent_supplement_4gpu_mb4_acc16_<time>_<pid>`.
The original group itself and directories inside its five old model folders
are reserved and cannot be used as new output directories.
Its `experiment.json` records source paths/fingerprints, generated config
hashes and finalized checkpoint fingerprints. `launch.env` is generated by the
helper using shell-quoted paths. Stale initialization/debug/batch settings in
the calling shell do not change this recipe. The source recipe must still be
the original eight-GPU run; four-GPU supplements preserve its global batch
by doubling accumulation rather than changing the learning rate.

Before long training the launcher runs a real CUDA SDPA/Flex prefix/gradient/
checkpoint check, followed by a **4- or 8-rank FSDP SHARD_GRAD_OP**, BF16, compiled
Flex and real FP32-master optimizer regression: two updates with sixteen or
eight accumulation passes respectively for each new mode. Neither check downloads Target weights
or reads images. Any check/training failure stops later training/evaluation.

## Automatic evaluation

After all three models finish, the finalizer checks their effective recipes
and epoch-5 exports, rechecks the old controls, and compares these eight models:

```
full recent256 recent128 recent64 pivot1 pivot5 pivot12 recent0
```

All benchmark cells include same-GPU AR. B=1, greedy, max_new_tokens=256.
AR-mismatching requests remain in the measured statistics.

1. One queue per assigned GPU over eight datasets: GSM8K, CharXiv, TextVQA, Flickr30k, HR-Bench 4K,
   HR-Bench 8K, VideoDetailCaption, Video-MME; **32 samples each**, including
   videos. The old frozen `eval_all_b1_n32` selection is reused, so normalized
   question fields are not reinterpreted and raw data is not resampled.
   Video-MME keeps the existing description protocol, not official QA accuracy.
2. MathVista + GovReport long context: **32 samples, repeat=1**, short/8k/32k/64k.
   Reuse the prepared 100-record directory (`LONGCTX_DATA_DIR`); a two-sample
   short/maximum-length smoke check gates formal evaluation. All eight models
   use identical length variants. Four jobs occupy the first four GPU selectors.

Both comparison tables include **ac len** (accepted Draft tokens), **Committed**
(including the Target token), throughput/AR ratio, token matches and peak
allocated memory. The long-context CSV/JSON additionally include ratios to
Full, prefill/decode/total timings, separate first/later Draft profiling and
final Draft KV/raw-hidden storage. The all-dataset table retains its existing
decode-only timing protocol. One evaluation failure is reported and does not
prevent the other evaluation suite from being attempted.

Set `EVAL_GPUS` / `LONGCTX_GPUS` to change the evaluation queues. To evaluate
again without training, set `RUN_GROUP` to the completed supplement and run
`bash tests/evaluate_dflash_recent_supplement.sh`. Fresh evaluation subdirectories
are created; optional `RECENT_EVAL_RESULT_DIR` / `RECENT_LONGCTX_RESULT_DIR`
must also be fresh.

The generic long-context entry remains backwards compatible. New Recent models
require `--supplement-run-group /path/to/completed/supplement`; their exports
must match its finalized manifest and reference the same experiment-1 group.

## Validation and limits

`tests/test_dflash_recent.py` exercises real Torch CPU loss/backward, per-block
training/inference parity, hidden-independence, block isolation, zero-cache
storage, bounded storage release, checkpoint reload and tiny multimodal Target
generation. Its sequential static check uses the installed native Qwen cache
to isolate the new no-hidden path without the server-specific transaction
extension. `tests/test_dflash_recent_supplement.py` checks recipe provenance,
frozen-input integrity, mixed checkpoints and the actual shell launchers with
stand-in training/model processes. Existing context and evaluation regressions
cover the unchanged controls. CPU checks do not establish CUDA performance or
four/eight-GPU correctness; the automatic CUDA/FSDP checks must pass on the server.
